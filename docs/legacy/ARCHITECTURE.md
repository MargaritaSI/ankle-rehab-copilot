# Архитектура и обоснование (reasoned workflow)

Документ для жюри и для разработчика, который захочет повторить проект.
Отвечает на 6 вопросов: зачем этот use case, зачем Job/Endpoint, как устроен
ingestion, как пользователь получает ответ с источниками, какие ограничения,
как воспроизвести.

---

## 1. Почему выбран этот use case

После ортопедической операции (здесь — перенос костно-хрящевого аутотрансплантата
в таранную кость, OAT) пациент тонет в противоречивой информации: форумы, блоги,
реклама добавок. Доказательная база разбросана по сотням статей PubMed, читать
которые без подготовки тяжело.

**Задача:** инструмент, который отвечает на конкретные вопросы восстановления
(нагрузка по неделям, отёк, упражнения, питание, добавки, гормональная терапия)
**строго по опубликованной литературе, с цитатой на каждый тезис**, и честно
говорит «нет данных», когда источников нет.

Это попадает в критерии челленджа: educational (учит читать доказательную базу),
real-world useful, и полностью **воспроизводимо** — корпус публичный.

## 2. Почему здесь нужен и Job, и Endpoint

Это не «обёртка над одним вызовом LLM». Нагрузка естественно делится на два типа:

| | Что делает | Почему именно так |
|---|---|---|
| **Serverless Job** | Тяжёлый batch: тянет сотни статей, режет на ~50k чанков, считает эмбеддинги, **семантически классифицирует каждый чанк по тегам** (inflammation / cartilage / rehab / nutrition / edema / hormones / recovery-factors / surgery), строит FAISS-индекс | Это разовая, ресурсоёмкая, конечная работа. Job отрабатывает и освобождает compute — платишь за минуты, не за простой. |
| **Serverless Endpoint** | Живой OpenAI-совместимый сервис (vLLM + Qwen2.5-7B): принимает вопрос, получает top-k фрагменты, формулирует структурированный ответ с цитатами | Это долгоживущий интерактивный сервис с публичным HTTP. |

Разделение — суть продукта: **индексация и инференс имеют разный профиль нагрузки**,
и serverless позволяет не держать GPU включённым между запросами.

## 3. Как устроен ingestion pipeline

```
corpus/topics.py     ~40 поисковых запросов по теме (публичные)
        │
corpus/fetch.py      Europe PMC REST API → Open-Access полнотекст (XML→текст)
        │            retry+backoff на 503, пропуск уже скачанных
        ▼
corpus/raw/*.txt     чистый текст + шапка (PMCID, title, year, journal, topic)
        │
job/index.py  [JOB]  чанкинг (220 слов, overlap 40)
        │            эмбеддинги MiniLM (нормированные)
        │            СЕМАНТИЧЕСКАЯ РАЗМЕТКА: косинус чанк↔описание тега ≥ порог
        ▼
corpus/index/        faiss.index + chunks.pkl (chunks, metas, tags)
```

Ключевое: Job делает **не только эмбеддинги**, но и zero-shot классификацию по
тегам — отсюда фасетный поиск и фильтры в UI.

## 4. Как пользователь получает ответ с источниками

```
вопрос ─▶ endpoint/rag.py
   embed вопроса (MiniLM) ─▶ FAISS top-k  [+ фильтр по тегам]
   фрагменты ─▶ Nebius Endpoint (Qwen2.5-7B), системный промпт «только из
                источников, каждый тезис с [PMCID], без воды, не диагноз»
   ─▶ структурированный ответ
   + EVIDENCE PANEL: реальные выдержки из статей + ссылки на PMC + теги
```

Дополнительные режимы (продуктовая глубина):
- **Compare mode** — сравнить, что литература говорит по двум темам/подходам.
- **Questions for specialist** — сгенерировать 5 вопросов врачу по теме.
- **Фильтр по тегам** — сузить поиск до inflammation / nutrition / rehab и т.д.

## 5. Ограничения системы (честно)

- Отвечает только тем, что есть в корпусе из ~700 Open-Access статей. Нет статьи —
  «нет данных» (это фича против галлюцинаций, не баг).
- **Не диагноз и не назначение.** Объясняет механизмы и что описывают протоколы,
  но не интерпретирует личную ситуацию за врача.
- Эмбеддинги — компактная MiniLM (скорость/стоимость); более крупная модель дала
  бы чуть лучший retrieval.
- On-device, без серверной валидации; корпус — только публичные данные, без
  персональных/пациентских.
- Темы по самомассажу/точной норме воды тоньше — мало РКИ в литературе.

## 6. Как другой разработчик это повторит

```bash
git clone <repo> && cd leg-recovery-rag
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python corpus/fetch.py --per-topic 15     # собрать корпус (бесплатно)
python job/index.py                        # индекс + теги (локально ИЛИ как Job)
#   как Nebius Job:  nebius ai job create --file job/job.yaml

# поднять LLM-endpoint на Nebius (см. endpoint/deploy.md), затем:
export NEBIUS_BASE_URL=... NEBIUS_API_KEY=... NEBIUS_MODEL=Qwen/Qwen2.5-7B-Instruct
streamlit run app/app.py
```

Полностью детерминированно: те же `topics.py` → тот же корпус → тот же индекс.
Никаких приватных данных и ключей в репозитории.
